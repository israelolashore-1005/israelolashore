# Israel Olashore Portfolio — Vite + Secure Admin

This version converts the portfolio into a Vite project and includes a secured server-backed admin dashboard.

## Included features

- Vite multi-page setup (`index.html` + `admin.html`)
- Existing portfolio design and assets retained
- Animated loading screen using the website logo
- React, Vite, Python and SQL included in the About/Skills section
- Responsive website previews with fullscreen/expanded viewing
- Hidden admin entry by double-clicking the main header logo
- Admin email + password login
- Server-side credential validation (credentials are not bundled into browser JavaScript)
- HttpOnly, SameSite session cookie
- CSRF protection for admin mutations
- Login rate limiting after repeated failed attempts
- Admin logout and session expiry
- Add portfolio websites from admin
- Client Project / Demo Concept selection
- Custom category and description
- Expand/collapse previews in admin
- Delete projects with a confirmation step
- Server-managed project data shared by all visitors

## Admin login

Double-click the logo in the main website header. This opens `/admin.html`, where the admin must sign in before the dashboard is displayed.

The project includes a private local `.env` so it works immediately after installation. **Change the temporary credentials before deploying or committing the project anywhere.**

To set your own credentials, edit `.env`:

```env
ADMIN_EMAIL=your-admin-email@example.com
ADMIN_PASSWORD=use-a-long-unique-password
SESSION_SECRET=use-a-long-random-secret
PORT=5173
NODE_ENV=development
```

`.env` is excluded by `.gitignore` and should never be committed to GitHub.

For deployment, set `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `SESSION_SECRET`, and `NODE_ENV=production` in the hosting provider's server environment settings rather than uploading the `.env` file.

## Production build

```bash
npm run build
npm start
```

The production server serves the Vite build and the protected API from the same application.

## Important deployment note

Because the secured admin now uses a Node/Express server and writes project changes to `data/projects.json`, deploy it to a host with a persistent Node server/filesystem or replace that JSON storage with a database for serverless platforms.

For platforms such as Vercel/Netlify where filesystem writes are not persistent between serverless invocations, use a database (for example Supabase/Postgres) for permanent project storage.

## Security behavior

- Knowing `/admin.html` is not enough to access admin actions.
- The email/password are checked only on the server.
- The browser receives an HttpOnly session cookie, so frontend JavaScript cannot read it.
- Admin POST/DELETE requests require both an authenticated session and a CSRF token.
- Five failed login attempts from the same IP trigger a temporary lockout.
- Sessions expire after eight hours and are cleared on logout.

## Project data

Initial projects are stored in:

```text
data/projects.json
```

Do not edit this file while the server is processing an admin change.
